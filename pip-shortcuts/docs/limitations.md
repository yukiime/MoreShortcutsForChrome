# 方案 3 开发备忘：缺点与待办

记录日期：2026-10-03。版本：0.2.0。目的：给自己留一份当前状态，后续继续开发时能想起哪些目标还没完成、哪些问题见过、哪些行为只写了代码但还没实测。每次复测后更新对应条目和日期。

## 窗口层级与遮挡

**未实现完整目标：其他应用在浮窗上方，浮窗在 Chrome 上方。** 历史版本出现过切换其他应用后浮窗仍置顶遮挡。现实现尝试在 Chrome 失焦时最小化 PiP，这个退路只是隐藏窗口，没有把它放到其他应用下方。

如果 Chrome 拒绝最小化，或更新后实际状态没有变为 minimized，后台向可信来源页发出关闭请求，来源页关闭自己的 PiP Window。代价是不能保留同一浮窗；回到 Chrome 后需要用户点击重新启动。恢复失败还会暂停并报错，不能保证每次返回 NTP 自动恢复。

相关控制器和关闭令牌有自动回归测试，当前 0.2.0 的真实跨应用失焦、隐藏和恢复闭环仍未完成运行验收。后续复测重点：切换应用后是否仍遮挡、浮窗是否消失、是否需要反复重启。

## 透明底板

此前实测已移除文档背景，但 Chrome 原生 PiP 底板仍不透明，曾显示黑色底板。当前代码还没有实现整个桌面窗口透明，0.2.0 未重新实测这一点。后续要看实际窗口底板，不能只检查 CSS 背景。

## 工具栏单击入口与来源标签

0.2.0 自动准备不激活的 source.html 后台标签，等待页面就绪后启用工具栏按钮。首次准备期间按钮可能暂不可用。点击路径尝试直接 requestWindow，再在点击所属窗口打开 NTP，省去前台控制页二级点击。

**这条最终路径尚未完成真实浏览器单击启动验收。** 浏览器可能拒绝用户激活传递，或来源页准备、窗口发现和注册失败。失败时工具栏显示 `!`；悬停查看错误，也可进入扩展选项页刷新诊断。选项页“手动测试”使用管理页本身持有 PiP，是单独的测试路径，不能证明日常工具栏路径已通过。手动测试期间需要保留管理页。

日常路径依赖后台会话标签。关闭、刷新或导航来源标签会使当前 PiP 或会话失效；后台重新准备标签不等于自动重建浮窗。关闭浮窗、重载扩展或重启 Chrome 后也需再次点击。无法保证完全没有辅助标签或无点击常驻恢复。

Chrome 官方说明 PiP 为置顶窗口，不能比打开它的窗口存活更久，requestWindow 需要用户手势。因此来源生命周期和重新创建手势是这条方案的实质约束。[Document Picture-in-Picture 官方说明](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)

## 窗口识别与恢复位置

实现通过创建前后窗口快照寻找唯一新增的 normal、alwaysOnTop 窗口，并核对来源和一次性令牌。API 未暴露可验证窗口、出现歧义或来源变化时会拒绝注册并关闭本次自己创建的 PiP，不猜测其他窗口 ID。这保护窗口归属，但部分浏览器环境可能无法运行。

记录的尺寸和位置会尝试恢复，Chrome 是否接受不能由保存成功推断。全屏、Spaces、多屏、显示器变化、窗口最小化和跨平台恢复尚无完整矩阵。切换多个 Chrome 主窗口的目标、导航后焦点和页面归属也需要当前版本实际复测。

与其他画中画窗口同时使用的行为还没验收。复测前先关掉视频或其他 PiP；另单独记录并发时是否替换已有会话。

## 功能缺口

- 没有历史“常访问”二级菜单，也不申请 history 权限。
- 清单在管理页编辑或粘贴 JSON，没有逐条名称和网址编辑表单。
- 数据与方案 1 独立保存，没有跨方案同步或自动迁移。
- 暂不提供商店签名安装包、系统辅助程序或对其他应用窗口层级的原生控制。
